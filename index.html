01

The Brief

Every call into Customer Care starts the same way: an agent checking four or five disconnected systems just to answer one question. The AS/400 has the order. The OMS has the line items and production stage. A carrier portal has the tracking number. A separate inventory feed has the actual stock. And whatever was said on the last call usually lives in a spreadsheet, if it was written down at all.

This wasn't a client brief — it started as a self-directed concept, built to make the case for something better before asking anyone to fund it. The goal was a single working screen: search a name, a phone number, or an order number, and get the full picture back — account, current order, live shipment status, real-time stock by size, and the call history — without a single tab switch.

No backend, no live system connections. Just a working interaction model, built on sample data shaped like the real thing, concrete enough to hand to a room and say this is what it could feel like.

02

What It Does

Customer & Order Lookup

Search · shipment · notes

One search bar takes a name, a phone number, or an order number and returns the whole account: contact info, lifetime order count, the current order's line items with live per-size stock badges, and a stitched status tracker — a dashed gold line that fills in as the order moves from Ordered to Delivered, a small nod to the embroidery on the uniforms themselves. Call notes sit directly beneath the order, logged inline, so the next agent to pick up the phone isn't starting from zero.

Inventory Lookup

Live stock · by size

A second mode on the same search bar — switch tabs and the same input now searches items and SKUs instead of customers. Stock is broken out by every size the warehouse carries, each tagged In Stock, Low Stock, or Backordered, with a restock date surfaced the moment a size runs out. An agent can give a real ship date on the first call instead of promising a callback.

03

Under the Hood

There's no backend here — the interesting decisions were about making a concept concrete enough to argue for, without touching a single production system or a real customer record.

SAMPLE DATA

Real shape, fictional records

Three sample customers and six sample SKUs stand in for the AS/400, the OMS, the carrier API, and the warehouse feed — shaped like the real integrations so the interaction model can be evaluated honestly, without wiring up production systems or exposing real customer data just to pitch an idea.

SIGNATURE DETAIL

A stitched status tracker

The shipment tracker uses a dashed line that fills solid gold as an order advances — styled after the stitching on the uniforms Varsity Spirit actually ships, so the one piece of UI unique to this brand is also the one carrying the order status, not a generic progress bar borrowed from anywhere else.

THE PITCH

Prototype first, then the case for it

Once the screen worked, the next artifact wasn't more code — it was a nine-slide deck built to bring the concept to leadership, using this prototype as its own proof-of-concept screenshot rather than a mockup. Its impact slide deliberately ships with dashed, unfilled metric boxes: a place to drop real numbers in once a pilot actually runs one, instead of inventing them to make the pitch land.
